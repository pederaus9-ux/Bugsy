## Confirmed finding and minimal recommendation

**MAJOR for the audio lifecycle qualification gate:** an already running ambient loop keeps producing master output while the game document is hidden. The behavior is demonstrated in native local Chromium. Automatic background silence is the new qualification criterion inferred from the runtime's existing hidden-aware sound guards; no physical speaker/phone outcome is claimed.

Cause: the farm sound timer in `index.html:3794` returns immediately when hidden. It therefore never calls `ambience()` to update the existing wind/rain loop gains to zero. `game.js:1954` computes a hidden-aware target only when that function is called; its looping BufferSources remain active afterward. `applySound()` at `game.js:1857` gates the shared master only on `snd.on`, and no visibility listener reapplies a hidden-aware master gate. Music avoids scheduling new notes while hidden, but that does not stop persistent ambient buffers.

Recommend a narrowly scoped change to make the shared master gain depend on both the user's sound preference and document visibility, and reapply it on native visibility changes. On return, keep a previously muted preference muted; preserve gesture/autoplay behavior. The [unapplied review sketch](tests/evidence/phase7n-audio/recommended-fix.patch) shows the two-line candidate. It has **not** been applied or tested as a fix.
