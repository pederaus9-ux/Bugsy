It avoids Object3D/Skeleton constructors, which generate random UUIDs. Geometry/material remain shared read-only, never disposed by the shadow. The preview has **6/6 focused checks passing**. The 24 independent idle/walk/run/turn/support/feed/drink/lie cases at 30/60/120 Hz compare complete animation state and transforms exactly and all **761,472** displayed vertex positions at the existing `1e-8` m comparison tolerance (31,728 vertices per case). Tests preserve live/base snapshots, shared geometry hash, request data and RNG; they detect manual-matrix/anchor/state mistakes and omitted support/care. Additional 36 consecutive frames cover lie/feed/drink transitions at the three rates with transformed scene ancestry. These are test-fixture equivalence results, not mobile/rendered or full lifecycle qualification.

Exact comparisons, including signed zeros, now pass; no oracle normalization was introduced. `preview-sequence-corrected.log` records the 11-check combined run (six preview plus five then-existing interval checks), exit 0, 767.486 ms.

## Animated-bound result and exact remaining proof

`tests/helpers/cow-skin-interval.mjs` is an interval affine-skinning kernel, **conditional on valid whole-time-domain bone-matrix intervals**. Matrix multiplication and weighted skinning preserve Three's operation order, original non-unit Float32 weight sums and affine translations. Basic arithmetic expands to adjacent representable doubles; no collision padding or test tolerance is reduced. Missing bounds, non-finite/projective coefficients and negative weights fail explicitly. Triangles lie in the convex hull of their three bounded vertices, but this does not supply their temporal transform intervals.

The interval kernel has **6/6 checks passing** (`interval-negative-final.log`, 590.862 ms): every actual vertex in a posed/translated rig; the retained real breathing midpoint RED using the analytic `sin in [-1,1]` scale domain; a continuously rotating/scaling/translating affine family; missing-limb/projective/nonfinite controls; exact dyadic rounding; and deliberately wrong normalized-weight algebra. The first rounding fixture incorrectly used decimal literal `.3` as the exact sum of the binary inputs `.1` and `.2`; `preview-interval-candidate.log` retains it. The replacement compares exact integer dyadic representations and rejects the unexpanded floating-point result. It does not change any physical tolerance.

**Not proved yet:** whole-interval matrix ranges for all real limb IK/anchor-release branches, attention transitions, terrain support and care overlays. The complete rig's continuous movement therefore remains uncertified. Sampling shadow poses, taking endpoint extrema, or passing the affine kernel tests cannot supply that missing premise. The helper is not used by gameplay. It does not claim retained post routes or every care corridor are now safe. Plane support is the only supported preview sampler; terrain/step support needs its own bounded domain.

The next useful implementation boundary is the interval provider, not another point-radius exception: derive limb-target/pose ranges from the current state and the actual `updateCow3D`/`poseCowLeg` branch conditions; split or union uncertain stance/release transitions; include support/care transforms. Require analytic enclosure plus adversarial interior witnesses, then pass those ranges into the skin kernel. Preserve the actual reset-state contract now tested. The existing spec's executable-care-corridor requirement must still pass, so an arbitrarily huge all-angle envelope that freezes cows is insufficient. Before any protected integration, record exact scope/preimage digests.

## Research and limits

- [Three.js SkinnedMesh documentation](https://threejs.org/docs/pages/SkinnedMesh.html) distinguishes current-pose bounds from animated updates. The checked-in `applyBoneTransform` source was inspected to match its actual bind/weight/affine order, rather than assuming a normalized convex blend.
- [Kavan and Zara, 2005](https://users.cs.utah.edu/~ladislav/kavan05fast/kavan05fast.pdf) supplies the discrete skin-bound/BVH direction. Its rotation-only assumptions are not silently extended to this rig's scale/translation or temporal motion. Our affine interval kernel addresses that algebraic part; the continuous joint-domain provider remains missing.
- [Akenine-Moller, 2001](https://fileadmin.cs.lth.se/cs/Personal/Tomas_Akenine-Moller/code/tribox_tam.pdf) explains triangle/box SAT; the diagnostic uses the existing Three implementation with focused controls. This is discrete collision evidence, not continuous-collision proof.

The direct all-vertex interval check costs about 0.47 s in this Node harness, so it is a reference proof path, not an acceptable per-frame game implementation. A production solution needs precomputed influence data and on-demand/refined bounds, followed by actual browser/device cost checks. No rendering or mobile-performance claim is made here.
