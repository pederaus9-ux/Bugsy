# Ground placement overlay design before implementation

Use the existing cream/green native editor and actual 3D ground. Keep the edit controls and gesture contracts. The overlay answers whether the selected snapped operation fits, not whether land is owned.

- Mark one-metre candidate anchor positions for the current selected structure, whole pen, post/edge/run move, or positions along a selected gate's current fence. Preserve current orientation, other geometry, ownership and command snapping. Gate attachment and width changes invalidate results.
- A solid green tile with a check means the complete candidate passes the same validation used by Apply. A muted red hatched/crossed tile is blocked and has a concrete reason. A dotted neutral tile is not checked or still checking. Legend text repeats these meanings, with readable contrast and44px controls. The selected item's footprint/access preview remains visible so an anchor tile cannot be mistaken for fitting arbitrary geometry.
- Pointer hover or a touch inspection updates the inspected location/reason only. It does not dispatch a live edit, move an actor or save. Existing drag/nudge commands still make drafts. Results describe exact snapped positions, not every point between samples. Unknown distant positions never borrow a nearby green result.
- Bound the visible neighborhood and queued candidates. Execute full geometry/care/route validation in one worker, with bounded one-at-a-time jobs; retain the same production ground sampler and complete World. Reuse the editor's command semantics on isolated draft data. Cache only within a matching selection/draft/obstacle/actor-care snapshot. Discard stale results and terminate pending work on close/replacement.
- Profile the real46 World first: current full validator is approximately0.7s per candidate in Node on this host. Do not place repeated synchronous full checks on the render thread. A definite static rejection may short-circuit only through an optional shared-validator path; green always requires all care/routes. Default Apply behavior and original tests remain intact.
- Revalidate on Apply. Error/unavailable worker states show unknown, never valid. Measure responsiveness, stale rejection, lifecycle/disposal and unchanged saved/draft state. Real390x844/1280x720 screenshots and native touch/pointer/keyboard probes precede owner visual review; other prescribed viewport journeys remain tracked.

This design is covered by A5 but not visually accepted. First complete and checkpoint the access restriction/native recovery slice. No image mockup or generic map tint substitutes for the real game.
